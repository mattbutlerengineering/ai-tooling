## What it does

The original terminal AI pair-programmer — git-aware, repo-map-driven edits across many files with automatic commits, works with most LLMs (Claude/GPT/local), voice + image input, and a built-in benchmark harness.

Mechanism: aider builds a tree-sitter "repo map" of the git repo's definitions (ranked by cross-file references, fitted to a `--map-tokens` budget), sends it plus the files you `/add` to an LLM, parses the reply as SEARCH/REPLACE blocks (or whole-file / udiff formats), applies them, and makes a git commit per change.

## How we tested it

**Evidence:** RUN

**Hands-on** — installed it via `pip install aider-chat` into a fresh venv (aider 0.86.2, 72s) and ran `aider --show-repo-map` and `aider --message` against a disclosed fixture repo, with the LLM endpoint replaced by a local canned-reply HTTP server (no API key or model credentials exist in the sandbox). The repo-map half is the real tool on real input; the edit half exercises aider's apply/commit/reflect machinery with scripted model replies, so it says nothing about how good a real model's edits are.

```
# fixture: /tmp/eval-aider/fx — 9 Python files (8 modules x [2 classes x 3 methods + 4 helpers] + app.py), 1,221 lines, 48 top-level symbols, git-committed
$ OPENAI_API_KEY=dummy aider --model gpt-4o --show-repo-map --map-tokens {256,1024,4096} --no-analytics --yes
budget 256 : map 464 tok (o200k), top-level symbols shown 29/48, files 8/9
budget 1024: map 2083 tok (o200k), top-level symbols shown 48/48, files 8/9
budget 4096: map 2586 tok (o200k), top-level symbols shown 48/48, files 9/9
baseline (cat every file): 10,155 tok (o200k)

# edit loop: OPENAI_API_BASE=http://127.0.0.1:8765/v1 aider --model openai/gpt-4o --edit-format diff --no-stream --map-tokens 0 --message "change it" pkg/mod0.py
exact SEARCH block        -> "Applied edit to pkg/mod0.py" + "Commit 2255d75 Changing the return value."; diff = 1 line changed
SEARCH with wrong indent  -> rejected, 3 automatic reflection round-trips ("Only 3 reflections allowed, stopping."), file and git history untouched
SEARCH on absent code     -> same: rejected after 3 reflections, tree untouched
naive baseline (python str.replace of the same SEARCH text): applies 1/3 (exact only)
```

## Test design

- **Task/corpus:** the synthetic 9-file fixture above (generated by a ~15-line script, all definitions known), plus three scripted model replies: exact match, indentation-mismatched SEARCH, SEARCH on code that does not exist.
- **Baseline:** for the map, dumping every source file (10,155 tokens); for edit application, an exact `str.replace` of the same SEARCH text.
- **Metric:** top-level symbols visible in the map (of 48), map size in tokens (tiktoken `o200k_base`), edit applied / committed / tree-clean per scenario, count of LLM round-trips.
- **Reproduce:** build the fixture, run the aider commands above; serve a fixed chat-completion JSON on 127.0.0.1:8765 for the edit arm. n=1 per cell; the map is deterministic, the fixture is synthetic and small.

## What worked

- Repo map is real and cheap: at a 1,024-token budget every one of the 48 top-level symbols was visible, at roughly a fifth of the 10,155-token full dump (2,083 vs 10,155 under our tokenizer). Even the 256 budget still surfaced 29/48 symbols across 8 of 9 files.
- Exact edits applied cleanly and produced a one-line git commit whose message came from the model reply, so the change is reviewable and revertable with ordinary git.
- Bad edits fail closed: both non-matching SEARCH blocks left files and history untouched and triggered an automatic retry loop capped at 3 reflections.
- Works against any OpenAI-compatible endpoint via `OPENAI_API_BASE`, which made it testable with no credentials.

## What didn't work or surprised us

- The core job — a real model producing correct multi-file edits — was not exercised: no model credentials exist here, so edit quality, repo-map ranking usefulness for real tasks, and the cost of a real session are unmeasured.
- Map size overshoots the stated budget under a standard tokenizer: `--map-tokens 256` produced 464 o200k tokens and 1024 produced 2,083 (aider estimates by sampling; the figure is approximate).
- The map is not selective on this fixture: from 1024 up it contains the same 48 symbols, so the budget knob only mattered at the low end; whether ranking by references (app.py imports mod0 and mod3) helps was not separable in a synthetic repo.
- On this three-case set aider's applier gave the same outcome as a naive exact `str.replace` (applied 1, rejected 2); no fuzzy-match advantage showed up, though three cases cannot rule one out.
- First run silently appended `.aider*` to `.gitignore` of the target repo (an untracked change in the user's tree).
- Install pulls a large dependency tree (litellm, tree-sitter grammars, numpy, scipy); 72s on a warm network.
- Last upstream push is 2026-05-22, about five months before this run.

## Quality signals affected

| Signal | Impact | Evidence |
|--------|--------|----------|
| Correctness | neutral | Apply/reject behaviour was correct on 3/3 scripted cases; edit correctness with a real model is unmeasured. |
| Speed | neutral | No timing was captured; no end-to-end task timing exists. |
| Maintainability | + | One git commit per change keeps history reviewable; map gives the model structure without whole-file dumps. |
| Safety | + | Failed edits left the tree untouched; edits are plain git commits. Side effect: modifies .gitignore. |
| Cost Efficiency | + | Map at 1,024 budget was ~20% of the full-dump token count on the fixture (synthetic; real savings depend on repo). |
| Verifiability | + | Every change lands as a diffable commit and failures are reported with the offending block, so a human can confirm the output. |

## Verdict

**discovery-log — tentative read** — the repo map and apply/commit/reject machinery run as documented offline and fail safely, but the tool's actual job (model-driven edits) needs credentials we lack, so no verdict-grade read is possible; a human or credentialed run should compare it against opencode on a real task before any promotion.
