# AI Tooling

Documentation-only repo. No build, test, or deploy commands.

## Purpose

An operating manual for AI-assisted development that produces high-quality code and keeps improving. Inventory and evaluation of AI tools, skills, agents, frameworks, harnesses, workflows, and MCP servers — organized around the dev loop stages where tools intervene and the quality signals they move.

Evaluates tools against six quality signals: Correctness, Speed, Maintainability, Safety, Cost Efficiency, and Verifiability (can a human confirm the output is right, at the rate it's produced — see ADR-0004). Evals written before Verifiability existed record five; it is required for new evals, not retrofitted. The workflow has three layers per stage (process, tooling, infrastructure) connected by feedback arcs that make each cycle better than the last.

## Structure

- `PLAYBOOK.md` — the one-page front door: what to install / how to work / what to watch, routing to the depth docs (hand-maintained router, never a data mirror)
- `CATALOG.md` — flat inventory of 667 tools, organized by 13 categories with overlap markers
- `WORKFLOW.md` — dev loop stages (inner + outer), tools per stage, quality signals, adoption guide
- `STACK.md` — recommended stack (~25 tools to actually install, with commands)
- `STACK-LEDGER.md` — machine-readable record of why each ADOPT/KEEP tool is/isn't in STACK (data foundation for the #70 drift gate)
- `evaluations/` — hands-on tool evaluations following `TEMPLATE.md`
- `methodologies/` — external AI-native SDLC methodologies mapped onto our dev loop + stack (synced to plugin; see ADR-0003)
- `discovery/` — historical bulk discovery logs (loops 1–21); new scans are GitHub issues labeled `scan` (see discovery/README.md)
- `skills/` — source skills for reference
- `plugin/` — installable Claude Code marketplace package (skills, docs, hooks)
- `README.md` — repo overview with install instructions

## Catalog format

Each entry is a row in a markdown table with these columns:

| Column | Description |
|--------|-------------|
| Name | Tool name, linked to repo |
| Type | tool / skill / plugin / framework / harness / platform / MCP server / reference |
| One-liner | Plain-language description, ~10-15 words |
| Problem it solves | The specific pain point, ~1 sentence |
| Overlaps with | Other catalog entries that address a similar problem (may also name a notable external tool or installed skill as a conceptual peer) |
| Ships inside | The `owner/repo` this artifact is a *component of*, when it is not independently installable — else empty (#343) |

**The `Ships inside` column (#343).** A row for a skill that ships inside a pack is
not an independent lead: installing the pack settles it, a redundancy verdict against
its own container is meaningless, and the queue overstates the work by one slot per
facet. The column makes that containment **explicit and machine-readable** instead of
leaving it to be re-derived (badly) from names — `triage.py` bands a declared row into
**P5 ships-inside**, ahead of even the mechanical bands, because a contained row's own
license and archival state answer a question about the *container's* artifact, not its
own. Detector X reports a fully-declared group as `DECLARED` rather than counting it.
Three rules:

- **The container is a slug, never a display name.** Same root as #366 and #374 — a
  basename is not a synonym. `mattpocock/skills`, not `skills`.
- **Empty is the default and means "independently installable".** Most rows are.
  Filling it wrongly *hides* a real lead, which is the expensive direction.
- **The `## Catalog entry` mirror in `evaluations/` stays five columns.** Width is
  derived from each table's own header (`catalog_lib.validate_catalog_rows`), so the
  ~520 existing mirrors are valid as-is; bumping the constant would make every one of
  them a detector O finding. Copy the 6th cell into a mirror only if you also widen
  that mirror's header.

## Source of truth

- Root files (`CATALOG.md`, `WORKFLOW.md`, `evaluations/`) are authoritative
- `plugin/docs/` is a synced copy — never edit directly
- `plugin/skills/` is authoritative for skills; `skills/` is derived (paths stripped)
- Run `./sync-plugin-docs.sh` after any root doc or plugin skill change
- `plugin/CLAUDE.md` is **hand-authored and stays that way** — it is the plugin's front door (skills list, hooks, `${CLAUDE_PLUGIN_ROOT}` paths), not a copy of root `CLAUDE.md`, so `sync-plugin-docs.sh` has nothing to mirror. The cost is that it drifts silently: its eval count sat 87 behind (#302) and its quality-signal list stayed at five for the whole life of the sixth signal (#313). The rule is therefore **gate the shared facts, not the file** — every fact it restates from root must have a generator or a test (counts → `reconcile-counts.py`'s `EVAL_PATTERNS`/`TOTAL_PATTERNS`; quality signals → `TestPluginFrontDoorSignals`). Restating a root fact here without one is the bug.

### Supported harnesses (Claude Code + opencode)

opencode is a supported harness alongside Claude Code. Both read this `CLAUDE.md`
(opencode reads it as its rules fallback — there is intentionally no `AGENTS.md`
content fork). Canonical homes per artifact, with the other harness derived/synced
(ADR-0002; never hand-maintain a duplicate that drifts):

- **Instructions** → `CLAUDE.md` (both harnesses)
- **Repo skills** → `.claude/skills/` + `.agents/skills/` (both harnesses auto-discover; `.claude/skills/find-skills` is a symlink to `.agents/skills/find-skills`)
- **Specialized agent (`eval-runner`)** → `.opencode/agents/` canonical; `.claude/agents/eval-runner.md` is a symlink to it (one source file, zero drift)
- **Hook logic** → opencode plugins in `.opencode/plugins/` (`commit-gate.ts`, `auto-sync.ts`) that call the **same** `audit-evals.py --offline` / `sync-plugin-docs.sh` scripts Claude Code's hooks use — so the local opencode, local Claude Code, and CI (`make check`) gates reference one implementation
- **Deterministic gates** → custom commands `/check` `/fix` `/sync` (opencode) and `make check`/`make fix`/`./sync-plugin-docs.sh` directly

**Lockstep invariant:** any change to a hook behavior must keep the opencode
plugins, the Claude Code `.claude/hooks/` scripts, and `.github/workflows/integrity.yml`
in lockstep — they all gate against the same coupled scripts, so they must not drift.

## Integrity audit

- **`make check` is the canonical gate; `make fix` is the canonical repair.** `make check` runs the full gating set in `--check`/verify mode — exactly what `.github/workflows/integrity.yml` enforces (the lint gates `ruff`/`mypy`, offline detectors B/D/G/J/K/O, `--selftest`, the `test_automation` unit suite, `reconcile`/`backfill`/`check-stars`/`verify-installs`/`tier-stack`/`sync-plugin-docs` `--check`, and the network install resolver A) — and exits non-zero on the first failure. `make fix` runs the apply-mode fixers in dependency order (`reconcile-counts` → `backfill-evidence` → `tier-stack` → `sync-plugin-docs`) then re-runs `check`, so a clean exit means the tree is green. CI's `audit` job calls `make check`, so the local and CI gate sets can't drift (pinned by `test_automation.py`'s `TestIntegrityMakefile`). The individual scripts below are still runnable directly when you want one gate in isolation.
- `python3 audit-evals.py` runs the gating detectors (A install, B fabrication, D verdict sync, G comparison consistency, J stack-derivation drift, K verdict evidence, O row shape) and exits non-zero on any problem (gate it in CI/pre-commit); opt-in detectors C/E/F/I and `--selftest` add more checks:
  - **install resolver** — every install command in `STACK.md`/`CATALOG.md`/`evaluations/` must point at a real artifact (npm/PyPI/crates.io/GitHub). A broken command means the tool was likely never run. (`--installs` only)
  - **fabrication classifier** — each eval's "How we tested" must either disclose it was not run or show a verified hands-on run; a section asserting a specific run with no honesty disclaimer is flagged. (`--fabrication`/`--offline`, no network)
  - **verdict sync** — each eval's `## Verdict` must agree with its `COMPARISON.md` row (tolerates dual verdicts and the KEEP/installed status). (`--verdicts`, offline)
  - **comparison consistency** — `COMPARISON.md`'s per-stage summary must sum to its own body rows and its Total must equal the `CATALOG.md` entry count; catches manual count drift between the two authoritative files. (`--comparison`, offline, gating, on by default)
  - **stack-derivation drift** — `STACK.md` must be derivable from the verdict data + the `STACK-LEDGER.md` exclusion ledger (#64): every ADOPT/KEEP tool is in STACK or has a logged exclusion reason, ledger verdicts match `COMPARISON.md`, and nothing marked in-STACK is actually missing from `STACK.md`. Kills the hand-maintained drift prior audits kept finding (abtop/codeburn, serena, documentation-writer). (`--drift`, offline, gating, on by default)
  - **verdict evidence** — a strong verdict can't rest on a README skim: an ADOPT/KEEP eval must be run-backed (`Evidence` `MEASURED` or `RUN`) **or** carry an explicit honesty disclaimer in its "How we tested" section; a `REVIEW`/`SOURCE-ONLY` ADOPT/KEEP with no disclaimer fails. The escape hatch is the same not-run disclaimer vocabulary the fabrication classifier (B) recognizes (the `HONEST` regex — "source-grounded", "not run hands-on", "did not install", etc.); widen that vocab if it false-flags an honest review. To clear the gate, either graduate the eval to MEASURED/RUN (#68) or add the disclaimer. (`--verdict-evidence`, offline, gating, on by default)
  - **row shape** — a malformed table row in `CATALOG.md`/`COMPARISON.md` used to be silently skipped by the parse sites, quietly corrupting the counts detector G gates on; validation now lives in `catalog_lib` (`validate_catalog_rows`/`validate_comparison_rows`) and any unrecognized or wrong-width entry row, or a per-stage COMPARISON row whose Evaluated cell isn't a verdict token, is a gating finding with its file and line number. (`--rows`, offline, gating, on by default; #198)
  - **link rot** (opt-in `--links`, ~450 requests) — every `github.com/owner/repo` link in `CATALOG.md` must resolve to its canonical name; flags 404s (dead) and silent renames (moved). **Read the `n/total checked` count, not just the verdict**: only a 404 means "gone", and every other failure (429 rate limit, 5xx, timeout) is *could not check*, reported as `INCONCLUSIVE` and never as OK (#319). Unauthenticated HEAD bursts of this size are heavily rate-limited — a local run typically verifies only a few dozen of the ~600 links, while the scheduled CI sweep gets through. Findings are always real; **absence of findings is only a pass when the checked count equals the total.**
  - **archived repos** (opt-in `--archived`, ~450 `gh api` calls, report-only) — flags catalogued repos GitHub marks `archived` (unmaintained); the entry should carry a ⚠️ archived note or repoint to a successor. Link rot misses these (the link still resolves). Note whether each is already disclosed.
  - **skill evidence** (opt-in `--skills`, report-only) — lists ADOPT-verdict *skill* evals that have a measured eval vs the review-based backlog; a tracked metric, not a gate (see issue #38 and the skill-eval guidance in `TEMPLATE.md`).
  - **skill test-design** (detector S; opt-in `--skill-design`, report-only) — counts every *skill*/plugin-Type eval that records at least one skill dimension (a Triggering test or a with-skill-vs-baseline A/B) vs those that record neither, per `TEMPLATE.md`'s required "Test design — skills" section (#38). Broader than `--skills` (all skill/plugin evals, not just ADOPT) and structural rather than verdict-based. Conservative by design — an eval counts as compliant on any triggering/A/B vocabulary, so an honest measured eval is never false-flagged; widen the vocab if it does, don't tighten it into a gate. A tracked metric, not a gate (mirrors `--skills`); gating new skill evals is the natural follow-up once the count stabilizes.
  - **dangling overlaps** (opt-in `--overlaps`, report-only) — an "Overlaps with" token naming a tool that isn't itself catalogued is either a deliberate external/conceptual peer (allowed) or a real gap; the more rows cite the same token, the likelier a gap (how `aider`/`continue`/`agenta` were found). Surfaces candidates for human review; not a gate. **The legend's "installed skill" case is now demonstrated rather than assumed** (#398): `CATALOG.md`'s own column legend says a token may name "a notable external tool **or installed skill**" — so *it's an installed skill* is the sanctioned reason a token doesn't resolve, and nothing checked it, which is the unchecked install assertion ADR-0006 removed from `KEEP` one file over. F now joins the same records detector Y reads (`~/.agents/.skill-lock.json`, `installed_plugins.json`, `~/.claude/skills/`) and splits the bucket: a token an install record answers to is an **installed-peer**, printed with the source slug and **never counted** (V's `acked`, W's `cleared`, X's `FACETED`, Y's `SHADOWED`), while everything else stays a candidate. **`(ext.)` was the same shape and is now verified rather than obeyed** (#403): F skipped any token carrying the marker, so a row could assert a tool was outside the catalog and never be contradicted once it was added — which is exactly what happened to `aider`. F found it, `9be01ee` catalogued it as a ★46K harness, the three rows that raised the flag went on calling it external, and F's own comment held one of them up as its example of a healthy row; six markers named a catalogued tool. A marked-external token whose identity resolves is now a **STALE-EXT** finding and it is **counted**, because it is a defect in the row rather than a peer awaiting review. Keyed on `identity_keys`, **never** `alias_keys` (#374): an alias-keyed run "resolves" `MCP (ext.)` to `mdn/mcp` by slash-basename, and between two rows that each name a tool a basename is not a synonym. `aider-style` is the mirror case — a descriptor rather than a name, so no key resolves it and only a human can repoint it. Repointing is not cosmetic: a dangling token contributes no `overlap_pressure`, a `triage.py` input, so `aider` sat at `discovery-log` carrying three invisible citations. Two further disclosures F can already read are also printed and never counted, asked **strongest-record-first** because a declaration is a fact about the artifact while an install record is a fact about one laptop (ADR-0006's split): a **contained-peer**, where the token's *own parenthetical* names a catalogued row — the `Ships inside` idea (#343) done informally, in the one column that has no such column, and the container is printed rather than swallowed because a parenthetical is prose that says where a peer lives, not that it isn't also a gap — and a **repo-peer**, a skill this repo ships under `skills/`, which is the strongest record available and the only one readable in CI (`skills/evaluate-tool/` is a real conceptual peer of a skill-evaluation tool and can never be a catalog row). Two of the legend's own examples still behave differently, now for a better reason — `tdd` is demonstrated by an install record, `systematic-debugging` by the container its citing row already disclosed. **Local-only, like Y**: `--overlaps` is opt-in and report-only so it never runs in CI, and with no records readable F reports precisely as it did before — the headline states the record count, because **0 records means "this machine keeps none", never "nothing is installed"**. Two scoping rules survive the split: **never narrow the skip vocabulary to make the count look worse** — the 16 genuinely-external markers must keep passing untouched, since flagging a healthy row costs more than missing a sick one (detector V's rule) — and **a settled bucket is not a cleared one**: F at zero means every token now resolves to something nameable, never that no gaps exist, because F can only see tokens somebody wrote down.
  - **WORKFLOW↔STACK drift** (opt-in `--workflow-drift`, report-only) — the operating manual (`WORKFLOW.md`) and the install list (`STACK.md`) must not give a newcomer two different answers to "what do I use for X". Enforces a one-directional invariant: every STACK *pick* (matched by github `owner/repo` slug, lowercased — not display name, since "GSD" links to `obra/superpowers`) must appear somewhere in `WORKFLOW.md`; the reverse is NOT required (WORKFLOW legitimately lists non-STACK CONDITIONAL options). Picks are scoped to STACK's install-command table rows, so the "excluded (#37)" prose (brooks-lint, code-on-incus) and self/issue links aren't mistaken for picks. Prints a count so it's "a number to shrink"; report-only, not a gate — gating it in `make check` is a later #70/#71-style decision (the `--overlaps` lifecycle is the precedent). (`--workflow-drift`, offline)
  - **staleness sweep** (`--staleness`, report-only) — flags evals whose `**Last verified:**` date is older than its category threshold (`STALENESS_DAYS`, keyed by Type — fast-moving harnesses/MCP servers/frameworks age in ~120 days, tools/skills/plugins ~180, references ~365; tune in one place). A point-in-time eval rots — a harness can be wrong months after it was written. The `**Last verified:**` field is now **mandatory**: `python3 backfill-lastverified.py --check` gates its presence in `make check` (exits non-zero listing any eval missing it), and the sweep itself runs inside `make check` as a non-failing report trailer (the `-`-prefixed `audit-evals.py --staleness` line) — so the report is visible every gate run while a merely-stale eval never fails CI (only *presence* is gated; making staleness itself gating is a later decision). `python3 backfill-lastverified.py` populates the field once across every eval, deriving a **floor date** from each file's last git edit (`git log -1 --format=%as`) and tagging it with a `<!-- backfilled from last git edit; not a hands-on re-check -->` comment so a floor is never mistaken for a real re-verification; it never overwrites a hand-set date. When you genuinely re-check an eval, replace the whole line (fresh date, drop the comment). Add the date to `TEMPLATE.md`'s header pattern for new evals.
  - **metadata staleness** (`--metadata-staleness`, report-only) — ages `repo-metadata.json`, the committed snapshot of GitHub facts the triage bands rest on. It rots in **one direction**: a repo archived after our last refresh keeps its `archived: false` record, so it never reaches the P1 successor-check band and nobody is told. Reports the record count, the oldest fetch and its age, and anything past `METADATA_STALE_DAYS` (120 — archival and relicensing move on a scale of months; tune in one place). Age comes from a per-record `fetched_at` stamp that `refresh-metadata.py` writes — `pushed_at` is the *repo's* push date, so a busy repo would look freshly-checked no matter how old our snapshot is. Records predating the stamp report as **undated** and are **never backfilled**: a floor date would assert a fetch that never happened (the `**Last triaged:**` rule, not the `**Last verified:**` one). `--stale` skips slugs already cached, so a full `refresh-metadata.py` run is what stamps them. Runs in `make check` as a second `-`-prefixed trailer beside the eval sweep, and unlike F/N this one can never *become* a gate: it would fail the build for a reason no code change caused, and its only fix needs the network the offline-gate invariant forbids CI from depending on. (`--metadata-staleness`, offline; #260)
  - **token-savings claims** (opt-in `--savings-claims`, report-only) — flags every `CATALOG.md` row whose one-liner makes a numeric token-savings headline (a `%` or `N×` next to token/reduction vocabulary) but whose eval is *not* run-backed (Evidence `MEASURED`/`RUN`). The Optimize cluster carries the loudest savings claims in the catalog (60–95% fewer tokens, 96% reduction, 50× token reduction) on the softest evidence; this turns that unverified backlog into a number to shrink by running the token-savings verification protocol (`evaluations/token-savings-protocol.md`). An in-row `self-reported`/`unverified` disclaimer is bucketed apart as the honest path (like detector B's `HONEST` vocab). A tracked metric, not a gate (mirrors `--skills`); gating it is a later #71-style decision. (`--savings-claims`, offline)
  - **evidence-strength field** (opt-in `--evidence`, report-only) — tallies each eval's declared `**Evidence:**` field (`MEASURED`/`RUN`/`REVIEW`/`SOURCE-ONLY`), recording *how hard we looked* separate from the verdict (*what we concluded*), catalog-wide and within the ADOPT/KEEP set ("what % of ADOPT is MEASURED"). Backfilled across every eval and mirrored as a column in `COMPARISON.md` (#67); gating weak-backed ADOPT/KEEP verdicts is #71. See `TEMPLATE.md` for how to choose a value.
  - **lead headline overreach** (detector T; opt-in `--lead-headlines`, report-only) — a `discovery-log` row says the tool was never exercised, so its eval is notes; if that eval's `## Verdict` nonetheless headlines something other than `discovery-log` or `SKIP` at `REVIEW`/`SOURCE-ONLY` evidence, it is claiming a verdict ADR-0005 does not grant it. 324 evals headlined `**CONDITIONAL**` this way until #324 relabelled them; T is what keeps them relabelled. Scoped to weak evidence on purpose: a `MEASURED`/`RUN` eval has *earned* its CONDITIONAL, and there the stale half is the row — a human's verdict call, not a headline defect this detector can name. Report-only because the survivors are escalations awaiting a human (#259), not build breakers; gating it is a later #71-style decision. (`--lead-headlines`, offline; #324)
  - **catalog-entry mirror drift** (detector U; opt-in `--catalog-mirror`, report-only) — `TEMPLATE.md` has every eval close with a `## Catalog entry` copy of its `CATALOG.md` row. That is a fact restated in ~520 places with **no generator and no test**, which is precisely the failure root `CLAUDE.md` names for `plugin/CLAUDE.md` — *gate the shared facts, not the file* — and it drifted the same way (#345). Four kinds, reported apart because they are not equally dangerous: **LINK** (eval and catalog name different repos — a rename repoints the catalog row and never the eval, leaving it to assert a dead slug plus the stars/license it was written against; #336, and `herdr` was SKIP-eligible on exactly this), **ORPHAN** (an embedded row naming no catalogued tool), **TEXT** (one-liner/problem/overlaps cells disagree — not cosmetic, since `triage.py` bands leads from the overlaps cell, which is how `softaworks/agent-toolkit` landed in the wrong band), **AMBIG** (two catalog rows collapse to one `name_key` — `agent-skills` vs `agentskills` — so the mirror can't be identified; resolution is exact-name-first for this reason, and an ambiguous fallback resolves to nothing rather than to a coin flip, which is what made the detector's first run report a LINK against the wrong tool's row), and **CASE** (URLs differing only in capitalization, which GitHub redirects — held out of LINK so that bucket stays actionable, but printed rather than filtered, per the no-silent-caps rule). Offline: a string comparison between two files already in the tree, unlike detector C's ~450 requests. Report-only, and deliberately **not** a bulk fixer — a wholesale rewrite in either direction destroys real work in the other, because the eval side is sometimes the better text (`azure-skills`); a human resolves each row. **Unlinked catalog rows are indexed for identity, and only their URL comparison is skipped** (#401): an entry with no repo to link (`server-github`, *"DEPRECATED, archived — superseded by github-mcp-server"*) is still a catalogued tool, and excluding it made its own eval's mirror a false `ORPHAN` — detector F already draws exactly this line (*unlinked entries name-match only*). Indexing it is not excusing it: once the row resolves, its cells are compared like any other's, so the finding becomes **true** rather than absent. The `ORPHAN`/`CASE`/`LINK`/`AMBIG` buckets are pinned at zero by a live-tree test; `TEXT` deliberately is **not**, because that is the bucket #345 sequenced as a human's per-row call. Reading the non-TEXT residue once was worth more than its count: it held the detector bug above, two mirrors whose Name cell had drifted off a renamed catalog row (`sentry-mcp` → `sentry`, `powerpoint skill` → `powerpoint`), a **recipe** that correctly has no row and now declares `## Catalog entry: n/a` with the reason, and `design-extract` — a tool carrying a written **CONDITIONAL** verdict that had no `CATALOG.md` row and no `COMPARISON.md` row at all, so detector D had nothing to sync against and G never counted it. That last one is the shape to watch for: `--catalog-mirror` was the only thing in the repo that noticed a tool had fallen out of the inventory, and it reported it as a formatting disagreement. (`--catalog-mirror`, offline; #345, #336, #401)
  - **maintenance signal** (detector V; opt-in `--maintenance`, report-only) — `triage.py`'s **P1 successor-check** band is `archived == true`, a clean structural signal that only catches maintainers who took the extra step of flipping GitHub's flag. `daytonaio/daytona` — ★72K, the catalog's canonical answer to "run untrusted AI-generated code" — announced discontinuation in its README in June 2026, moved core development to a private codebase, kept `archived: false`, and sat in **P3 backlog as ordinary un-examined work for two months** (#351). P1 reading "0 leads" presents as *nothing archived to check*; that is true and says nothing about how many catalogued projects are dead. V reports the two per-record signals `refresh-metadata.py --maintenance` writes: **`discontinued`** (the README banner phrase, quoted in the output so a human judges the phrase rather than trusting the regex) and **`license_lost`** (a real license that became `NONE`/`404` since the last snapshot — daytona went AGPL-3.0 → 404 while `vercel-labs/skills` went `NONE` → MIT, and detector R can see neither, since it ages the snapshot as a whole and both records were well inside the threshold). Deliberately **not** a `pushed_at` threshold: dormancy is not discontinuation, and the distinction is load-bearing — `plandex` was SKIPped at 13 months because a *coding agent* rots when model APIs turn over, while `ralph` was left at ~6 because an autonomous *loop* is a pattern over whatever harness you point it at. Sorted strongest-verdict-first, because a dead tool we still **recommend** outranks a dead lead nobody was going to reach. An uncollected signal reports **0 records**, never 0 findings — absence of the field means "not collected", never "nothing is dead". **A match is a candidate, not a disposition.** The regex finds the phrase; it cannot resolve the phrase's *subject*. The first collection run produced two classes of miss: `codex-plugin-cc` and `architect-loop` matched a bare `is read-only` that described a **command** (fixed by anchoring the pattern to the repo as subject, and pinned by tests — a detector that flags a healthy tool is worse than one that misses a dead one, because the miss costs a stale row and the false positive costs trust in every other finding); and `giskard-oss` matched "no longer actively maintained" said of Giskard **v2** while the repo ships v3, which no regex resolves. That second class is why the matched phrase is **quoted** in the output and why V never bands anything — a human reads the phrase. Because it is unfixable in code, it gets an **acknowledgment escape hatch**: a record may carry `discontinued_ack: {phrase, why}`, and a finding whose phrase matches is still *printed* (as `acknowledged false positive`) but not counted, so the headline stays a number to shrink. The ack **pins the exact phrase** — a README that later gains a genuine repo-level banner changes the phrase and reports again, so the hatch cannot become a mute button — it is scoped to `discontinued` only (a `license_lost` on the same record still fires), a malformed ack grants nothing, and `refresh-metadata.py` carries it forward on **every** path including the unreachable one, since a transient `gh` failure must not erase a human's judgement. Writing an ack is a human call; a bulk lane may not. Same root as #343 (identity by name inside the catalog) and #366 (on the filesystem): key on what the row *is*. Note what the collision cost beyond the two rows — it *withheld* a SKIP, so nothing was wrongly disposed, but it was also the only thing keeping `vercel-labs/agent-skills` out of P4, which made #372's `effective_license()` fix look like it changed nothing.
  - A `discovery-log` eval still carries a `## Verdict` line, and since #324 it **headlines `discovery-log` and says so**: `**discovery-log — tentative read** — …`. It used to borrow `**CONDITIONAL**`, a word ADR-0005 grants only to a tool we exercised (`Evidence` MEASURED/RUN) or one carrying a real `adopt-if:` gate — so a section titled `## Verdict` announced a verdict the eval wasn't entitled to, on 324 files. That nearly cost a whole triage lane: `/triage-lead` escalates a CONDITIONAL headline, which shielded 11 of 13 leads in one band. Promoting such a lead to a real verdict is the whole job. Key on the **headline** verdict (`ev.verdict`), never `verdict_set`: an eval reading "Held at CONDITIONAL rather than ADOPT" has `ADOPT` in its set and not in its headline. Detector T keeps the relabel from regrowing.
- `python3 refresh-metadata.py` refreshes `repo-metadata.json` (license, archived, stars, pushed_at) for every catalogued GitHub repo. **The only script that calls `gh`**, so `make check` stays offline and CI never depends on ~580 API calls — the same split as `audit-evals.py`'s offline gates vs its opt-in `--installs`/`--archived` passes. `--stale` fetches only slugs missing from the cache. `--maintenance` additionally reads each README's head for a discontinuation banner and flags a license that disappeared since the last snapshot, writing `discontinued` and `license_lost` per record for detector V (#351) — it **doubles** the call count, which is why it is opt-in rather than part of every refresh. A `404` license value records *unreachable* (renamed, deleted, or DMCA-blocked — see `vkhanhqui/figma-mcp-go`) and is deliberately distinct from `NONE`, which means the repo is live and GitHub found no `LICENSE` **file**. That last word is load-bearing and used to be missing: GitHub's licensee detector reads a root LICENSE file and nothing else, so a repo declaring MIT in its README or `package.json` records `NONE` exactly like a repo granting nothing — and P4 mechanical-skip disposes vendored leads on that value. **9 of 28 `NONE` records declared a license anyway**, and five carried a SKIP whose stated ground was the license (#372). So when the API reports no license, the refresher looks where a human would — a README `## License` section, then `package.json`/`pyproject.toml`/`Cargo.toml` — and records `license_declared: {spdx, where, phrase}` (plus `conflict` when the README and the manifest disagree, as `builderio/agent-native`'s MIT-vs-ISC does). It fires only on `NONE`, so it costs a few dozen extra calls in a ~600-repo run rather than doubling it, and it is re-derived every fetch rather than carried forward — a repo that later adds a real LICENSE file drops the field on its own. What it records is a **candidate, not a license**: a README line naming MIT without the license text or a copyright holder is a thinner record than a LICENSE file, and whether that clears the adoption bar is a human's call. What it is not is an *absence*, and only an absence can carry a mechanical SKIP. `triage.py`'s `effective_license()` is what reads it, and it resolves in **both** directions — a README declaring AGPL disqualifies a vendored artifact on exactly the reasoning a parsed AGPL does. A missing cache is not fatal: the structural bands go empty rather than the gate exploding.
- `**Last triaged:**` is an **optional** eval header field, written only when the triage lane actually examines a lead; its *absence* is meaningful, so it is **never backfilled** (unlike `**Last verified:**`, whose git-derived floor date is honest — a lead that was never triaged has no floor, and stamping one would assert a look that never happened). `triage.py` sinks stamped leads within their band so each pass surfaces genuinely un-examined ones and the queue converges instead of re-shuffling. **Every stamp must be attributed**: a bulk lane writes `<!-- triaged: bulk -->` beside the date and a human pass writes `<!-- triaged: human -->`, and detector Q fails an unattributed stamp. The marker is what makes eliminate-only mechanical rather than a promise — Q can only police a lane it can identify, so a bare date looks exactly like a lane that behaved (#327). The human marker exempts the eval from the verdict ceiling, because reaching a real verdict is precisely what a human pass is for.
- `python3 watchlist.py` regenerates `WATCHLIST.md` — the *revisit* companion to NEXT-EVALS.md (which is *first-time* priorities), one derived page of everything worth re-evaluating or watching so a maintainer no longer greps four scripts and three files. Four sections, each computed (not hand-maintained) from data already in the repo: (1) **Deferred** — every `DEFER` COMPARISON row with the re-evaluate trigger pulled from its eval's `## Verdict` (per TEMPLATE.md's DEFER definition; a missing trigger is itself an action item); (2) **Flagged for hands-on** — the STACK.md prose flags (`flagged for a hands-on eval` / `pending a hands-on eval`), grep-parsed (deliberately fragile — the durable fix is a machine-readable column in STACK-LEDGER.md); (3) **Stale / undated** — the `audit-evals.py --staleness` sweep; (4) **Unverified claims & measurement backlog** — the `--savings-claims` + ADOPT-skill `--skills` backlogs. Reuses the `audit-evals.py` detector functions directly via `DetectorContext` (never re-implements or shells out); `--check` gates it in CI. Nobody edits WATCHLIST.md by hand.
- `python3 -m unittest test_automation` (or `python3 test_automation.py`) runs the characterization tests for the count/sync automation — `reconcile-counts.py`, detector G (`audit_comparison`), detector J (`audit_stack_drift`), `sync-plugin-docs.sh`, the Evidence field/derivation, `backfill-evidence.py`, `tier-stack.py`, `check-stars.py`, and `verify-installs.py`. They pin current behavior against temp fixtures (never the real files) so the shared-parser refactor (#45) has a regression net; exits non-zero on failure and runs as part of `make check`, so CI enforces it (#202).

### Routines

Scheduled cloud agents (the daily discovery pass). **A routine lands its own PR: it merges to `main` once CI is green rather than parking the PR for review.** Branch `routine/<lane>-<YYYY-MM-DD>` off fresh `main`, never two open PRs from one lane, then `gh pr merge --auto --squash --delete-branch` — `main` requires the `audit` check, so GitHub holds the merge until CI is green and the routine can exit instead of babysitting it. This is about how a pass *lands*, not what it may *conclude* — eliminate-only still holds. See `docs/agents/routines.md` for the sequence and the do-not-merge list.

## Adding entries

- Use the `/add-catalog-entry` skill (`.claude/skills/add-catalog-entry/`) — it runs the full 8-file workflow (resolve slug, dedup, insert CATALOG + COMPARISON rows, propagate counts, sync, audit).
- Fetch repo description: `gh api repos/{owner}/{repo} --jq '.description'`
- Place in the correct category table
- Always fill the "Overlaps with" column — check existing entries in the same category
- Every row carries all **six** cells, including a `Ships inside` cell that is usually empty. Fill it (with an `owner/repo`, never a display name) when the artifact is a component of a larger one — a skill inside a pack, one server inside a monorepo. An omitted 6th cell is a detector O finding, not a legacy row.
- If a new category is needed, add a section header with a one-line description
- **Never hand-edit counts.** Run `python3 reconcile-counts.py` to propagate the catalog total across README/CLAUDE/STACK/plugin and rebuild COMPARISON's summary from its body rows (`--check` for a dry-run / CI gate). Detector G then verifies CATALOG == COMPARISON.

## Evaluations

- **Hands-on evaluations** use `evaluations/TEMPLATE.md` — copy it and fill every section with evidence from actual usage. The "How we tested it" section is mandatory; README-only evaluations are discovery logs, not evaluations.
- **Discovery logs** (`discovery/new-tools-loopN.md`) are the historical bulk-triage record — one-liner verdicts from scanning repos. They feed the catalog but don't constitute a full evaluation. New scans are GitHub issues labeled `scan` (see discovery/README.md), not new loop files.
- Use inner/outer loop vocabulary (Plan, Implement, Verify, Review, Ship, Reflect), not ACMM levels.
